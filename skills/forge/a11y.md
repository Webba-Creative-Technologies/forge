# Accessibility playbook

What Forge gives you for free per component, and what you still must add.

Forge maps components to WAI-ARIA roles and wires keyboard navigation by default. You still need to provide meaningful labels, focus management for dynamic flows, and page-level landmarks.

## Global

- All interactive primitives expose `:focus-visible` outlines in the brand color.
- `ForgeProvider` respects `prefers-reduced-motion`. You do not need media queries; components read `--motion-scale`. Override via `<ForgeProvider reducedMotion="auto" | "always" | "never">`.
- Color contrast: `darkTheme` and `lightTheme` both meet WCAG AA for `var(--text-primary)` on `var(--bg-primary)`. `var(--text-muted)` is AA for large text only. Do not use it for small body copy.

## Buttons

- `Button` sets `aria-busy` when `loading`.
- `IconButton` auto-populates `aria-label` from the `tooltip` prop. Either `tooltip` or explicit `aria-label` is mandatory.

**You add:** a meaningful label on every `IconButton`. Never ship `<IconButton icon={...} />` without one.

## Inputs

- `Input`, `Textarea`, `Select`, `NumberInput`, `PasswordInput`, `PhoneInput`, `OTPInput`, `Combobox` wire `aria-invalid`, `aria-describedby` to hint/error nodes, `aria-required`, and `role="alert"` on the error message.
- `Slider` has `role="slider"`, `aria-valuenow/min/max/text`, Arrow/Home/End/PageUp/PageDown keyboard support.
- `NumberInput` input has `role="spinbutton"` and `aria-valuenow/min/max`. The inc/dec buttons have their own `aria-label`.
- `Combobox` has `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded`.

**You add:** the `label` prop on every input. Never rely on placeholder as a label; placeholder disappears on focus.

## Overlays

- `Modal`, `Sheet`, `BottomSheet` have `role="dialog"`, `aria-modal="true"`. Pass `aria-label` via the `title` prop.
- `Dropdown` trigger has `role="button"`, `aria-haspopup="menu"`, `aria-expanded`. The menu has `role="menu"`.
- `Popover` trigger has `role="button"`, `aria-haspopup="dialog"`, `aria-expanded`. Content has `role="dialog"`.
- `Tooltip` content has `role="tooltip"`.

**You add:** a meaningful `title` on every `Modal`/`Sheet`. If you build a custom overlay, you are on the hook for focus trap, body scroll lock, and Escape handling; use `Modal` instead.

## Navigation

- `Tabs`, `Pills`, `PillTabs` expose `role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, `aria-controls`, `aria-labelledby`, and roving focus via `tabIndex`.
- `Accordion` items have `aria-expanded`, `aria-controls`, matching `role="region"` + `aria-labelledby` on the panel, and `hidden` while collapsed.
- `TableOfContents` gets an `aria-label` derived from `title`, defaulting to "Table of contents".
- `Breadcrumbs` uses native `<nav aria-label="Breadcrumb">`.

**You add:** nothing extra unless you wrap these in a larger landmark (`role="navigation"` with its own `aria-label`).

## Toggles and selectors

- `Switch` has `role="switch"`, `aria-checked`, `aria-label`, `aria-invalid`.
- `Checkbox`, `Radio` use native `<input>` semantics, so labels wire via `<label htmlFor>`.
- `Avatar` becomes keyboard-operable when clickable: `role="button"`, `tabIndex={0}`, Enter/Space handler. Always exposes `aria-label` derived from `name` + status.

**You add:** a meaningful `aria-label` on any `Switch` without a visible label next to it.

## Progress and feedback

- `ProgressBar`, `ProgressRing` have `role="progressbar"` and `aria-valuenow/min/max`.
- `Toast`, `Notification`, `Alert`, `Banner` act as live regions. `Alert variant="error"` fires `role="alert"` automatically.

**You add:** nothing. Use `Alert variant="error"` over a custom red `Text` so the live region fires.

## Tables

- `Table` uses native `<table>` semantics. Sorting triggers are `<button>` with `aria-sort`.
- Row selection uses native `<input type="checkbox">`.

**You add:** a `caption` or a sibling `<Text size="sm" color="muted">` summary above the table describing what it shows.

## Charts

Charts render to canvas or SVG and are not screen-reader readable by default.

**You add:** a hidden text summary near the chart. Minimum: "Bar chart, N categories, highest value X in category Y, lowest value Z in category W." Place the summary off-screen with `position: 'absolute', left: -9999` or a Forge `sr-only` helper if available.

## Keyboard flow checklist

Before claiming an interactive feature done:

- [ ] Every interactive element reachable by Tab in visual order.
- [ ] Enter and Space trigger the primary action on the focused element.
- [ ] Escape closes overlays (Forge handles this for `Modal`/`Sheet`/`Drawer`).
- [ ] Focus moves to the overlay on open and returns to the trigger on close (Forge handles this for `Modal`).
- [ ] Arrow keys navigate within radio groups, tab lists, menus, and sliders (Forge handles this).
- [ ] No keyboard trap: Tab eventually cycles out of any menu or dialog or moves to the document body.

## Quick fixes for recurring issues

- Icon-only button with no label: add `aria-label` or `tooltip`.
- Input with no label: add `label` prop. Do not rely on placeholder.
- Custom dropdown: use `Dropdown` or `Popover`; they wire `aria-haspopup` / `aria-expanded` correctly.
- Form error renders but no screen reader announcement: use the `Input` `error` prop (gets `role="alert"`) instead of a sibling `<p>`.
- Modal close button has no label: `<IconButton icon={<Dismiss20Regular />} aria-label="Close" />`.
- Motion too fast to read: make sure it is covered by `ForgeProvider`'s reduced-motion policy. Do not hand-roll CSS animations that ignore it.
